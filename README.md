# Solutions Support Bot

Telegram-бот проекта **Solutions Studio Project**: информация о студии, портфолио проектов,
прайс на рекламу, система тикетов поддержки, админ-панель, статистика, рассылки
и уведомления через дополнительный Telegram-аккаунт.

- Python 3.12, **aiogram 3** (Bot API 9.x), SQLAlchemy 2 (async), Alembic
- PostgreSQL (production) / SQLite (локально), Redis для FSM (необязательно)
- Telethon — только для дополнительного аккаунта уведомлений
- Docker + Docker Compose, healthcheck, автоперезапуск, корректное завершение

## 1. Установка

```bash
git clone <ваш-репозиторий> solutions-support-bot
cd solutions-support-bot
cp .env.example .env
```

Дальше — заполнить `.env` (раздел 2) и запустить локально (раздел 6) или через Docker (раздел 7).

## 2. Файл .env

Все секреты и настройки — только в `.env`. Файл в `.gitignore`, в код ничего не вшито.

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота от @BotFather |
| `ADMIN_IDS` | да | Telegram ID владельцев через запятую: `111,222` |
| `POSTGRES_PASSWORD` | для Docker | Пароль БД (латиница и цифры) |
| `POSTGRES_DB`, `POSTGRES_USER` | нет | Имя БД и пользователя (по умолчанию `support_bot`) |
| `DATABASE_URL` | для локального запуска | `sqlite+aiosqlite:///data/bot.db` или `postgresql+asyncpg://user:pass@host:5432/db`. В Docker собирается автоматически |
| `REDIS_URL` | нет | Redis для состояний диалогов. В Docker задаётся автоматически |
| `SUPPORT_MAX_TICKETS` | нет | Лимит одновременно открытых тикетов (по умолчанию 3; можно поменять и в админке) |
| `SUPPORT_USERNAME` | нет | Юзернейм для ссылки «Написать в ЛС поддержки» (без @) |
| `PORTFOLIO_URL`, `PORTFOLIO_CHANNEL_URL`, `COMMUNITY_CHAT_URL` | нет | Стартовые ссылки портфолио (дальше меняются в админке) |
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | для доп. аккаунта | С https://my.telegram.org |
| `SESSION_ENCRYPTION_KEY` | для доп. аккаунта | Ключ шифрования сессий (см. раздел 9) |
| `PREMIUM_EMOJI_ENABLED` | нет | `true`/`false` — premium-эмодзи в интерфейсе |
| `TIMEZONE` | нет | Часовой пояс для дат (по умолчанию `Europe/Moscow`) |
| `BROADCAST_RATE` | нет | Сообщений в секунду при рассылке (по умолчанию 20, максимум 30) |
| `LOG_LEVEL` | нет | `INFO` / `DEBUG` |

## 3. Где взять Bot Token

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Задайте имя и юзернейм (должен оканчиваться на `bot`).
3. Скопируйте токен вида `1234567890:AA...` в `BOT_TOKEN`.

Если токен неверный, бот при старте напишет в лог
`Telegram отклонил BOT_TOKEN` и завершится с кодом 1.

## 4. Telegram ID администратора

1. Узнайте свой ID, например в [@ScanMyIdRobot](https://t.me/ScanMyIdRobot).
2. Впишите в `.env`: `ADMIN_IDS=123456789` (несколько — через запятую).
3. Откройте бота и нажмите `/start` — внизу меню появится кнопка **«Админ-панель»**, или отправьте `/admin`.

Владельцы из `ADMIN_IDS` могут добавлять других администраторов прямо в админке
(**Администраторы → Добавить**). Снять владельца можно только в `.env`.

## 5. PostgreSQL

**В Docker ничего делать не нужно** — PostgreSQL 16 поднимается в `docker-compose.yml`,
данные лежат в volume `pgdata`, достаточно задать `POSTGRES_PASSWORD`.

Свой сервер PostgreSQL:

```sql
CREATE USER support_bot WITH PASSWORD 'strongpassword';
CREATE DATABASE support_bot OWNER support_bot;
```

```env
DATABASE_URL=postgresql+asyncpg://support_bot:strongpassword@localhost:5432/support_bot
```

Таблицы создаются **миграциями Alembic автоматически при старте** (`alembic upgrade head`).
Вручную: `alembic upgrade head`. Отключить автоприменение: `SKIP_MIGRATIONS=1`.

## 6. Локальный запуск

Нужен Python 3.12+.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

По умолчанию используется SQLite (`data/bot.db`) и хранение состояний в памяти.

## 7. Запуск через Docker

```bash
cp .env.example .env      # заполнить BOT_TOKEN, ADMIN_IDS, POSTGRES_PASSWORD
docker compose up -d --build
```

Поднимаются три контейнера: `bot`, `db` (PostgreSQL 16), `redis`.

| Действие | Команда |
|---|---|
| Логи | `docker compose logs -f bot` |
| Статус и healthcheck | `docker compose ps` |
| Перезапуск | `docker compose restart bot` |
| Обновить код | `git pull && docker compose up -d --build` |
| Остановить | `docker compose down` (данные сохраняются в volumes) |
| Бэкап БД | `docker compose exec db pg_dump -U support_bot support_bot > backup.sql` |

- **Автоперезапуск** — `restart: unless-stopped` у всех сервисов.
- **Healthcheck** — `GET /health` внутри контейнера: проверяет доступность БД и работу polling.
- **Корректное завершение** — `tini` передаёт SIGTERM, бот дожидается текущих обработчиков,
  останавливает рассылку и закрывает соединения (`stop_grace_period: 30s`).
- **Сохранение данных** — volumes `pgdata` (БД, в т.ч. зашифрованные сессии доп. аккаунта),
  `redisdata` (состояния диалогов), `botlogs` (файлы логов с ротацией), `botdata`.
- **Логи** — stdout (json-file с ротацией 5×10 МБ) + `/app/logs/bot.log` (ротация 5×5 МБ).

## 8. Деплой на VPS

Проверено для Ubuntu 22.04/24.04, Debian 12.

```bash
# 1. Docker
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker

# 2. Код
git clone <ваш-репозиторий> ~/solutions-support-bot
cd ~/solutions-support-bot
cp .env.example .env
nano .env                  # BOT_TOKEN, ADMIN_IDS, POSTGRES_PASSWORD

# 3. Запуск
docker compose up -d --build
docker compose logs -f bot # ждём «Бот @... запущен»
```

Бот работает через long polling — открывать порты и настраивать домен не нужно.
Контейнеры сами поднимутся после перезагрузки сервера (Docker запускается как сервис).

## 9. Дополнительный аккаунт (уведомления о тикетах)

Подключённый Telegram-аккаунт присылает уведомление о каждом новом тикете в обычный
чат (например, на ваш основной аккаунт) — такие уведомления сложно пропустить.

**Настройка:**

1. Получите `api_id` и `api_hash`: https://my.telegram.org → *API development tools*.
2. Сгенерируйте ключ шифрования:
   ```bash
   python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
   ```
3. Впишите в `.env`: `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `SESSION_ENCRYPTION_KEY` и перезапустите бота.

**Подключение из бота** (только владельцы): **Админ-панель → Доп. аккаунт → Добавить аккаунт**.

1. Номер телефона аккаунта.
2. Код из Telegram — **через пробелы** (`1 2 3 4 5`): Telegram аннулирует код,
   если его переслать в чат одним числом.
3. Пароль 2FA, если включён.
4. Кому слать уведомления: `@username`, числовой ID или «Избранное». Бот сразу отправит тест.

**Подключение из консоли сервера** (код не попадает ни в какой чат):

```bash
docker compose exec bot python -m scripts.connect_account
```

**Безопасность:**
- авторизуется только сам владелец аккаунта; бот ничего не перехватывает;
- код и пароль используются один раз в памяти, сообщения с ними бот удаляет, в БД их нет;
- сохраняется только StringSession, **зашифрованная Fernet** (`SESSION_ENCRYPTION_KEY`);
  без ключа она бесполезна. Не меняйте ключ после подключения — иначе подключите аккаунт заново;
- «Отключить и удалить» завершает сессию на стороне Telegram и удаляет её из БД;
- если аккаунт недоступен, бот продолжает работать, ошибка видна в карточке аккаунта и в логах.

## 10. Рассылки

**Админ-панель → Рассылка → Создать рассылку**

1. Отправьте сообщение: текст, фото/видео/GIF/документ с подписью, стикер, голосовое.
   Форматирование и premium-эмодзи сохраняются.
2. Добавьте кнопки или нажмите «Без кнопок». Формат — строка = ряд, кнопки через ` | `:
   ```
   Наш канал - https://t.me/channel | Сайт - https://example.com
   Поддержка - https://t.me/bot
   ```
3. Предпросмотр → «Начать рассылку» → подтверждение «Вы уверены?» с числом получателей.

Во время рассылки обновляется прогресс: получатели, успешно, ошибки, заблокировавшие бота.
Её можно остановить. Скорость ограничена `BROADCAST_RATE`; при ответе Telegram «слишком часто»
бот ждёт нужное время и повторяет — никто не пропускается. Заблокировавшие бота
помечаются и не попадают в следующие рассылки.

## 11. Проекты

**Админ-панель → Проекты**

- **Добавить проект** — пошагово: название → описание → username бота → число пользователей →
  ссылка → изображение (на необязательных шагах можно отправить `-`, чтобы пропустить).
- В карточке проекта: изменить любое поле, добавить доп. ссылки (`Канал - https://t.me/...`),
  скрыть/показать, поднять/опустить, предпросмотр, удалить.
- Порядок в админке = порядок в разделе «О нас».

При первом запуске заполнены проекты из канала «Solutions Studio Project [SSP]» и сайта-портфолио
(по состоянию на 22.09.2026): MOG BATTLE, Emoji Solutions Maker, Solutions Stories, Solutions Search,
Find Virus Referal, Scan My ID, Solutions AutoPosting, Solutions Savemode. Число пользователей указано
только там, где оно названо в материалах (15 000 / 3 000 / 1 500 — из поста в канале от 22.09.2026).

## 12. Главное меню

**Админ-панель → Главное меню**

Для каждой кнопки: текст, стиль (🔵 синяя / 🟢 зелёная / 🔴 красная / ⚪ обычная),
premium-иконка, ширина (весь ряд или половина), порядок, включение/выключение.
Можно добавлять свои кнопки-ссылки. «Предпросмотр меню» показывает меню так,
как его видят пользователи.

По умолчанию:

```
🔵 О нас
🟢 Реклама
⚪ Поддержка
🔵 Наше портфолио
```

**Тексты** разделов (приветствие, «О нас», «Поддержка», «Портфолио», «Реклама») — в
**Админ-панель → Тексты**. Отправляйте текст как обычное сообщение: жирный, курсив, ссылки
и premium-эмодзи сохранятся. Фото и стикер приветствия, username поддержки и лимит тикетов —
в **Настройки**.

**Premium-эмодзи интерфейса** настраиваются в одном месте — `config/emoji.py`
(`ABOUT_EMOJI`, `SUPPORT_EMOJI`, `PORTFOLIO_EMOJI`, `TICKET_EMOJI`, `ADMIN_EMOJI`, …).
ID берутся из `assets/premium_emoji.json` — выгрузки набора
[solutions_project_by_Solutmark_bot](https://t.me/addemoji/solutions_project_by_Solutmark_bot).

## Как устроена поддержка

**Пользователь:** Поддержка → Создать обращение → выбор темы → описание одним сообщением
(любой тип) → создаётся тикет `#1001`, `#1002`, … Дальше просто пишет в чат — сообщения
уходят в активное обращение; на ответ поддержки можно ответить reply. «Мои обращения» —
активные тикеты, их можно закрыть. Не больше 3 открытых тикетов одновременно
(«Вы достигли максимального количества активных обращений — 3…»).

**Администратор** получает уведомление «🔔 Новый тикет» с кнопками *Открыть тикет /
Ответить / Закрыть* и копию сообщения пользователя. Ответить можно тремя способами:

1. кнопка **«Ответить»** → режим ответа: всё, что вы отправляете, уходит пользователю
   (`/cancel` — выйти, `/quick` — быстрые ответы);
2. **reply** на любое сообщение пользователя в чате с ботом;
3. **быстрый ответ** из карточки тикета.

Пользователь видит сообщения от имени бота — технические детали скрыты.

Карточка тикета: пользователь, категория, время, статус, последние сообщения, полная история,
медиа из переписки, ссылки, «Взять в работу», закрыть (с причиной или без),
заблокировать/разблокировать пользователя. Список тикетов: фильтры *Все / Открытые /
В работе / Закрытые / Заблокированные* и поиск по номеру, Telegram ID, username, категории.

Статусы: `OPEN` → `IN_PROGRESS` (после первого ответа или «Взять в работу») → `CLOSED`;
`BANNED` — тикеты заблокированного пользователя.

**Ссылки тикета:** `t.me/<бот>?start=t1042` — пользователь открывает свой тикет;
`t.me/<бот>?start=adm1042` — админ открывает карточку;
`t.me/<username>?text=Привет, я из Telegram-бота…Номер тикета: #1042` — ЛС поддержки с готовым текстом.

**Реклама:** раздел с прайсом и кнопкой «Заказать рекламу» — она сразу открывает создание
тикета в категории «Реклама».

## Ограничения Telegram и что сделано вместо них

| Требование | Ограничение | Решение |
|---|---|---|
| Цвет кнопок | Произвольный цвет нельзя. Bot API 9.4+ даёт 3 стиля | Стили `primary` (синий), `success` (зелёный), `danger` (красный) и обычный — выбираются в админке |
| Premium Emoji в сообщениях и иконки кнопок | Доступны только ботам с юзернеймом, купленным на Fragment | Используются реальные ID из набора проекта. Если Telegram откажет, бот сам отправит обычные эмодзи и выключит premium до перезапуска — сообщение не теряется |
| Готовый текст в ЛС по ссылке | Telegram только подставляет текст в поле ввода, отправляет сам пользователь | Ссылка `t.me/<username>?text=…` |
| Кнопка «Открыть тикет» в уведомлении доп. аккаунта | Обычный аккаунт не может отправлять inline-кнопки | Ссылка `t.me/<бот>?start=adm1042` — открывает карточку тикета |
| Альбом в рассылке | `copyMessage` копирует одно сообщение | В рассылку отправляется одно медиа с подписью и кнопками |

## Структура проекта

```
solutions-support-bot/
├── main.py                 # точка входа: миграции → бот → polling, healthcheck
├── config/
│   ├── settings.py         # настройки из .env (pydantic-settings)
│   └── emoji.py            # все premium-эмодзи интерфейса в одном месте
├── bot/
│   ├── app.py              # сборка Bot/Dispatcher/сервисов
│   ├── callbacks.py        # типизированные callback data
│   ├── handlers/           # пользовательская часть: меню, поддержка, fallback
│   ├── keyboards/          # клавиатуры (стили, иконки)
│   ├── middlewares/        # сессия БД, пользователь, антифлуд
│   ├── filters/            # IsAdmin / IsOwner
│   ├── services/           # экраны, premium-страховка, healthcheck, блокировки
│   └── states/             # FSM-состояния всех сценариев
├── admin/
│   ├── handlers/           # тикеты, быстрые ответы, проекты, меню, тексты,
│   │                       # рассылка, статистика, блокировки, админы, доп. аккаунт
│   ├── keyboards/
│   └── services/           # рассылка, статистика + график, карточка тикета
├── support/
│   ├── ticket_service.py   # бизнес-логика тикетов
│   ├── message_service.py  # пересылка любых типов сообщений
│   ├── account_service.py  # доп. аккаунт (Telethon), шифрование сессии
│   └── deeplink.py         # deep links тикетов
├── database/
│   ├── models/             # ORM-модели
│   ├── repositories/       # доступ к данным
│   ├── database.py         # движок, сессии, миграции
│   └── seed.py             # стартовые данные сообщества Solutions
├── migrations/             # Alembic
├── scripts/connect_account.py
├── assets/premium_emoji.json
├── tests/                  # сквозные сценарии на фейковом Bot API
├── Dockerfile, docker-compose.yml, .env.example
```

Таблицы: `users`, `admins`, `banned_users`, `tickets`, `ticket_messages`, `ticket_message_links`,
`ticket_categories`, `projects`, `portfolio_links`, `menu_buttons`, `quick_replies`, `bot_settings`,
`broadcasts`, `broadcast_results`, `connected_accounts`.

**Безопасность:** секреты только в `.env`; права администратора проверяются фильтром на
каждом сообщении и нажатии во всей админке; callback data типизированы и валидируются —
подделанные данные не доходят до обработчиков; пользователь может открыть/закрыть только
свои тикеты; сессии Telethon зашифрованы, `*.session` в `.gitignore`; бот работает только в личных чатах.
